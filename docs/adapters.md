# External adapter compatibility

This repository invokes external executables, not vendored proxy source. Commands were inspected against Copilot proxy `0.10.28` and CLIProxyAPI `7.2.140` in the development environment. This is an interface reference, not a live-auth certification for arbitrary releases.

| Adapter | Required commands/features |
| --- | --- |
| Copilot | `auth`; `start --port PORT --api-key KEY`; `/v1/models`; `/v1/messages` |
| CLIProxyAPI | `-config FILE`; `-codex-login`; `-codex-device-login`; `-antigravity-login`; `-no-browser`; model and Messages endpoints |

Install versions that expose these interfaces, then check their own help/version. `proxyup doctor` checks executable presence and catalog access; it does not yet perform a full semantic-version compatibility handshake.

The Copilot adapter may use Node/Bun dependencies internally; this project's zero-dependency core does not install that runtime. CLIProxyAPI is a separately distributed binary. Use upstream installers/releases and inspect their authentication and licensing instructions.

Managed CLIProxy config sets its auth directory and local API key, disables nested request retries and cross-project/preview fallback. Provider/model classification prefers explicit `modelIds` overrides and then provider/owner metadata. No regex-only guess is used for unknown ownership.

External/attach mode never rewrites the external config or deletes its credentials. Supply its local API keys via the configured environment-variable names. Authentication for attached CLIProxy stays with that installation; commands generated by this project always reference its own managed config.

Before a release, manually check each selected adapter version using a disposable account/session: login, account catalog, one conversation, tool call round trip, cancellation and logout/disconnect. Do not put live credentials in CI or PR fixtures.
